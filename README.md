# AI Customer Support Ticket & Sentiment Analyzer
AI-powered customer support ticket analysis and sentiment classification using Python and machine learning.
A Python machine-learning prototype that analyzes customer support messages, predicts their category and sentiment, and assigns a rule-based priority to help support teams review incoming tickets more efficiently.

Link : https://colab.research.google.com/drive/1Fm42H3lxT6jOdUg6PJLUc6GLWNuniksg?usp=sharing

## Project Overview

Customer support teams receive tickets about billing, technical problems, accounts, orders, deliveries, refunds, and general questions. Reviewing and routing every message manually can take time.

This project demonstrates an end-to-end workflow that takes a customer message and returns:

- **Ticket category:** one of seven support categories.
- **Sentiment:** Positive, Neutral, or Negative.
- **Confidence scores:** model scores for the predicted category and sentiment.
- **Priority level:** Low, Medium, High, or Urgent, assigned through rules.

The prototype is designed to **support human agents, not replace them**. Sensitive cases—such as unauthorized payments, suspected fraud, or account-access problems—should still be reviewed by a person.

## Key Features

- Text preprocessing and TF-IDF feature extraction.
- Logistic Regression models for ticket-category and sentiment prediction.
- Rule-based ticket prioritization.
- An interactive interface built with `ipywidgets` in Google Colab.
- Functional checks using sample customer messages.
- Evaluation on a held-out test set.

## Dataset

The prototype uses a small custom dataset of **210 sample tickets**.

### Ticket categories

The dataset contains 30 tickets in each of these seven categories:

- Billing
- Technical
- Account
- Order
- Delivery
- Refund
- General

### Sentiment distribution

| Sentiment | Number of tickets |
|---|---:|
| Neutral | 85 |
| Positive | 70 |
| Negative | 55 |
| **Total** | **210** |

The reported split uses **168 tickets for training** and **42 tickets for testing**. Because the dataset is small and custom-built, it may not represent the variety of messages handled by a real support team.

## Methodology

### 1. Text classification

Ticket text is transformed into numerical TF-IDF features. Logistic Regression classifiers are used to predict the ticket category and sentiment.

### 2. Priority assignment

A separate rule-based function assigns a priority level using ticket information and predefined conditions. For example, a message reporting an unauthorized payment triggers an **Urgent** priority so that it can be reviewed promptly.

Priority is not a third machine-learning prediction in this prototype; it is generated by explicit rules. Those rules may miss unfamiliar wording or overreact to keywords, so their output should be checked by a human agent.

### 3. Interactive interface

A lightweight `ipywidgets` interface in Google Colab provides a text area, an **Analyze Ticket** button, and a results area. The output displays the predicted category, category confidence, predicted sentiment, sentiment confidence, and priority.

## Results

| Evaluation | Reported result |
|---|---:|
| Ticket-category accuracy | **88.10%** |
| Sentiment accuracy — initial version | 61.90% |
| Sentiment accuracy — improved version | **88.10%** |

The accuracy values come from the project's reported train/test experiment. The 7/7 result is a separate manual functional check on selected examples; it is **not** the same as test-set accuracy and does not prove performance on unseen real-world tickets.

### Example prediction

**Input ticket**

> Someone accessed my account and made an unauthorized payment.

**Prototype output**

|---|---|

| Category confidence | 38.40% |

The priority rule flags the unauthorized-payment wording for prompt review. The model confidence scores are indicators, not guarantees; the category score in this example is relatively low, reinforcing the need for human review.

## Limitations

- The dataset contains only 210 tickets and may not reflect real-world traffic.
- Results depend on the selected train/test split; one split does not establish reliable generalization.
- Overall accuracy does not show how well every individual class performs. Per-class precision, recall, and F1-score should be examined in further evaluation.
- Confidence scores are not calibrated probabilities and should not be treated as guarantees.
- Rule-based priority logic can miss context, synonyms, and unexpected wording.
- The prototype has not been deployed or validated for production use.

## Future Improvements

- Expand the dataset with more diverse, realistic, and carefully labeled tickets.
- Validate the models on a separate, independent dataset.
- Report per-class precision, recall, F1-score, and a confusion matrix.
- Review priority rules with experienced customer-support agents and test edge cases.
- Calibrate confidence scores and define when a ticket should be sent for manual review.
- Consider a secure web interface and integration with a ticketing platform only after further testing.

## Responsible Use

This is an educational prototype for decision support. Do not use its predictions as the sole basis for customer-impacting decisions. Human agents should review uncertain predictions and all high-risk or sensitive cases.
